# 数据保存与自动处理

## 任务、执行记录与审计永久保存

发布推送任务（所有状态）、每次执行记录、应用审计及全局运维审计均持久化到 MySQL，本服务不再按时间自动删除，也不提供保留天数配置。已移除 RetentionService、小时清理定时器、TASK_RETENTION_DAYS 和 AUDIT_RETENTION_DAYS；不需要数据库迁移。

更新并重启所有实例后生效，不能留下仍带旧清理任务的旧进程。部署环境中遗留的两个旧变量不再生效，可以删除。已经被旧版本或外部操作删除的记录无法凭本次改动恢复；迁移前未采集的记录也不会补造。

查询仍默认最近 30 天、单次时间跨度最多 90 天，并分页限制每页最多 100 条。这是查询资源限制，不是保存时长：可以传入多年前的 from/to，分段读取任意仍存在的历史记录。

上述 from/to 分段读取适用于提供这些参数的应用查询接口；当前全局审计 CLI `audit list` 仍返回默认窗口的第一页，本轮没有扩展 CLI 筛选参数。

## 全项目自动删除与过期逻辑核对

| 对象 | 当前处理 | 是否删除数据库记录 |
| --- | --- | --- |
| 发布任务、执行记录、应用/全局审计 | 永久保存，无清理任务 | 否 |
| 可补发用户/设备消息 ota_messages | 默认 24 小时有效，查询/重连补发时发现过期会删除；收到匹配 ACK 后删除；同一目标新消息覆盖上一条 | 是，属于待确认消息状态，不是历史日志 |
| API Key | 仅显式设置到期时间的 Key 会到期失效，永久 Key 不受影响；撤销记录也保留 | 否 |
| 发布目录缓存 | 5 秒有效，下一次读取时重新从数据库加载；策略更新可主动失效缓存 | 否，仅内存 |
| 在线连接、订阅与已推送状态 | 取消订阅或断线时清除 | 否，仅内存 |
| 发布任务租约 | 定时轮询发现到期后记录 lease_expired 并尝试接管/重试 | 否，保留原任务和执行记录 |

普通消息的 MESSAGE_RESEND_TTL_SECONDS 配置仍然有效；本轮没有取消消息 TTL、ACK 和“每个目标只保留最后一条待确认消息”的业务语义。消息到期不是后台定时批量清理，未被读取的过期行可能仍留在表中，但不会补发。

CLI 与业务服务统一使用数据库 host/port，不再提供独立 socket 配置。Worker 随服务启动自动轮询，没有任务暂停环境变量；维护时应停止全部服务实例，而不是依赖旧开关。隔离测试专用的 socket 由测试夹具注入，不属于产品配置。

运行时代码中剩余的数据库 DELETE 还有显式发布名单替换/切换为公共范围时的当前名单更新，伴随事务及差异审计；它们不是按时间清理。代码中没有自动删除发布版本、客户端上报/错误统计、API Key 或 OSS 更新包的定时任务；孤立 OSS 对象也不会自动回收。历史表退役属于运维显式执行的一次性数据库迁移，不是后台任务。

此核对仅覆盖仓库代码。外部 MySQL Event、OSS Bucket 生命周期、主机清理脚本或 PM2 日志轮转插件不由本项目控制，本轮没有连接业务数据库、OSS 或部署主机核实。服务端运行日志当前写本地文件，仓库未配置自动按天删除。

## 消息权限与来源 IP

IPS 配置及相关来源 IP 允许列表已删除；遗留 IPS 环境变量不再生效。管理消息发送/订阅查询仅依据 API Key 的显式应用授权及 messages:send/messages:read 权限，不保留 IP 放行或绕过认证的入口。

TRUST_PROXY_HOPS 和来源 IP 解析仍保留，用于审计及上报来源，不用于本项目的访问允许列表。API Key 校验、应用隔离、消息目标应用校验均继续生效。
